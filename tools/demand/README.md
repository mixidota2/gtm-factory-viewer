# 需要地図の記事と出典を照合する

学童・保育・機械警備の記事が対象です。検査は公表元の一覧と登録済みの原典を取得し、`index.html` に掲載した数字や出典と照らし合わせます。記事の編集や公開はしません。

公表元から資料を取得する検査と、手元のPDFを使う検査では、確認できる範囲が違います。公表元の一覧に新しい候補がないかも調べるなら、次の全体検査を使います。

## 手元で実行する

Python 3 と、Poppler に含まれる `pdftotext` が必要です。リポジトリのルートで次のコマンドを実行します。`--out` には、まだ存在しない出力先を指定してください。

```sh
python3 tools/demand/check_all.py --html index.html --out source-evidence
```

| 終了コード | 結果の読み方 |
| --- | --- |
| 0 | 今回の対象に限り、公式一覧・原典・保存済み記事が照合条件を満たしました。 |
| 3 | 確認が必要です。資料を取得できない、資料やリンクが登録内容と違う、照合結果が足りない、などの理由があります。`result.json` と各グループの記録を読んで理由を調べます。 |

## 手元のPDFだけを使う場合

学童・保育のPDFが手元にあるなら、それぞれのファイルを指定して照合できます。この手順では、今回渡したPDFと記事の対応を確かめます。公表元の一覧は取り直さず、機械警備も対象外です。PDFのハッシュが登録済みの値と異なっても、検査はそのPDFを新しい原典として自動では採用しません。

```sh
python3 tools/demand/demand-integrated/verify.py --html index.html --gakudo-pdf /path/to/gakudo.pdf --nursery-pdf /path/to/nursery.pdf --out saved-source-evidence
```

この手順の結果は出力先の `integration.json` にあります。記事データとHTMLはファイルの内容を比較する対象です。ブラウザーで画面を開いたり操作したりする検査ではありません。

## GitHub Actions の結果を読む

検査の実行ページにある要約には、学童・保育と機械警備の結果が別々に表示されます。詳しい結果は `source-evidence` にあります。要約にリンクがなければ、同じ実行ページの成果物欄とログを確認します。

全体の `result.json` でどちらの検査に確認が必要かを見て、`childcare/`（学童・保育）または `security/`（機械警備）の記録を開きます。一方の検査が失敗しても、もう一方は実行します。

- 一覧やPDFを取得できないときは、まず接続とHTTPの応答を確認します。取得できないことだけでは、公表元が資料を変えたかどうかは分かりません。
- 案内ページや公式一覧が変わったときは、何が変わり、どの候補PDFをまだ確認していないかを調べます。案内ページが変わっていても、登録済みの原典PDFは一致する場合があります。
- 取得したPDFが登録版と一致しないときは、どの版を取得したかを確認し、対象期間、定義、記事で引用した表を読み比べます。記事の数値が正しいか確認する前に、ハッシュだけを新しい値に置き換えません。

要約は検査が保存した結果を表示するだけです。検査の終了コードや公開の判定は変えません。

## 何を記録し、どこまで確認するか

検査が記録するのは、出典URL、取得結果、ハッシュ、照合対象の数値と照合結果です。同梱する検証用ファイルの SHA-256 は [manifest.json](manifest.json) にあり、原典URLと登録済みハッシュは各検証処理のファイルにも記載しています。

PDF全文はリポジトリに含めません。取得したPDF、一覧のHTML、PDFから抜き出したページ本文は手元での確認に使い、GitHub Actions が公開する成果物には含めません。

検査で確かめたのは、各処理が対象とした一覧・資料・表です。対象外に新しい資料がないことや、記事にあるすべての解釈が正しいことまでは分かりません。
