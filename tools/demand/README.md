# 需要地図の記事と出典を照合する

学童・保育・機械警備の記事を確認する手順です。公表元が出した資料と、`index.html` に載せた数値や出典を検査プログラムで照合します。検査は記事を書き換えたり、公開したりしません。

公表元の一覧に新しい資料の候補がないかも調べるなら、全体検査を使います。保存してある学童・保育のPDFと記事だけを比べる場合は、「手元のPDFだけを使う場合」を参照してください。

## 手元で実行する

全体検査には Python 3 と、Poppler の `pdftotext` が必要です。リポジトリのルートで次のコマンドを実行してください。プログラムが出力先を作るので、`--out` にはまだ存在しないパスを指定します。

```sh
python3 tools/demand/check_all.py --html index.html --out source-evidence
```

| 終了コード | 結果の読み方 |
| --- | --- |
| 0 | 今回の対象に限り、公式一覧・原典・保存済みの記事が検査の条件を満たしました。 |
| 3 | 確認が必要です。取得できなかった資料、登録内容と違う資料やリンク、照合に不足した結果がないかを `result.json` と各グループの記録で確認してください。 |

## 手元のPDFだけを使う場合

学童と保育のPDFを保存している場合は、次のコマンドで別々に指定して照合できます。検査は、渡したPDFと記事を照合します。公表元の一覧は取り直さず、機械警備も対象外です。PDFのハッシュが登録済みの値と異なっても、検査はそのPDFを新しい原典として採用しません。

```sh
python3 tools/demand/demand-integrated/verify.py --html index.html --gakudo-pdf /path/to/gakudo.pdf --nursery-pdf /path/to/nursery.pdf --out saved-source-evidence
```

結果は、出力先の `integration.json` を開いて確認します。検査が比べるのは記事データとHTMLファイルの内容です。ブラウザーで画面を開いたり操作したりする検査ではありません。

## GitHub Actions の結果を読む

実行ページの要約で、学童・保育と機械警備の結果をそれぞれ確認できます。詳細は成果物 `source-evidence` にあります。要約にリンクが見当たらない場合は、同じ実行ページの成果物欄とログを確認してください。

まず `result.json` で、どちらのグループに確認が必要かを調べます。学童・保育なら `childcare/`、機械警備なら `security/` を開きます。一方の検査が失敗しても、もう一方は実行します。

- **一覧やPDFを取得できなかったとき**：接続状況とHTTP応答を確認します。取得の失敗だけでは、公表元が資料を変更したかは分かりません。
- **案内ページや公式一覧が変わったとき**：何が変わったかを読み、まだ確認していない候補PDFを特定します。一覧が変わっても、登録した原典PDFは同じ場合があります。
- **取得したPDFが登録版と異なるとき**：取得したファイルを確認し、対象期間、指標の定義、記事で引用した表を読み比べます。数値の正しさを確認せず、登録ハッシュだけを更新しないでください。

要約は、検査がすでに保存した結果を表示するだけです。終了コードを変えたり、記事を公開したりはしません。

## 何を記録し、どこまで確認するか

検査は、出典のURL、取得結果、ハッシュ、照合した数値とその結果を保存します。同梱の検証ファイルのSHA-256は [manifest.json](manifest.json) にあります。原典のURLと登録済みハッシュは、各検証プログラムにも載っています。

リポジトリにPDF全文はありません。取得したPDFや一覧ページのHTML、PDFのページから取り出した本文は手元で確認します。GitHub Actions が共有する成果物には含めません。

結果から分かるのは、検査が実際に対象にした一覧・資料・表についてです。対象外に新資料がないことや、記事の解釈がすべて正しいことは確認できません。
